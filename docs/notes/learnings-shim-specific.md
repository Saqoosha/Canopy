# Learnings: Shim-specific

Condensed from CLAUDE.md. Full original text: `git show 3b6a198:CLAUDE.md`.

- **Never inject authStatus into `update_state`; `init_response` only** — it breaks logout/re-login. `tengu_vscode_cc_auth` must be forced true.
- **Extension responses are unwrapped, unsolicited messages are `{type:"from-extension", message:...}`** — dump the shape at your hook point (`CANOPY_CJK_DEBUG=1`), never copy a consumer's test.
- **CJK repair constraints** (`cjk-emphasis.js`, `cjk-emphasis-stream.js`) — flanking context is the last EMITTED code point; only non-ASCII punctuation moves; chunk splits must not change output, hence the held-back tail released before `content_block_stop`. `CANOPY_DISABLE_CJK_EMPHASIS_REPAIR=1` disables it.
- **Do NOT line-buffer the shim's stderr** — an undecodable chunk is dropped whole, so a residual glues across the hole and fabricates a line matching `process exited with code`. If built, make it `Data`-level.
- **An extension update can kill activation silently** — `ExtensionContext` (`context.js`) is a hand-written subset; a missing member (e.g. `workspaceState`) throws in `activate`, the shim exits 1 and the pane bounces to the launcher. Look for `Unknown ExtensionContext member:` and the `.error` log `Shim error: Extension activation failed`. The extension may replace its error with a fixed sentence ("An extension error was not caught…"); the frame then carries the real type and position from its `Activation failed:` output line (`activation-error.js`).
- **CC 2.1.331 starts a new conversation's CLI before the page's `init` when a `frame-probe` post answers `true`** — see `postMessage` in `window.js`, which answers `false`.
- **The update canary proves activation only** — it stops at `ready`, so it misses anything that shows when a CLI starts. It also passes when the webview provider fails: the extension logs `Uncaught exception: …` and rejects from `resolveWebviewView`, and `_activateFirstProvider` ignores that promise (reproduced on 2.1.331 by a review agent; 2.1.330 wraps it the same way). The extension's `uncaughtException` listener also swallows errors thrown by shim code after startup. Neither has been seen in a release; both are left as they are.
- **A CLI spawn does not mean a session start** — the extension also runs a config probe (`Loading config cache by launching Claude (no channel)...`, `spawnConfigProbe`, `CLAUDE_CODE_CONFIG_PROBE=1`). When `launch_claude` reaches the extension late after `init` (2.5 s in the rig, about 1.7 s after the probe in the app; not at 0.4 s), the probe's CLI runs its own set of SessionStart hooks and exits. 2.1.330 and 2.1.331 behave the same; left alone on purpose. In the log, `Launching Claude on channel` counts sessions; `Spawning Claude with SDK query function` counts both.
- **Diff the `vscode` API use before adding a new extension version** — collect the aliases of `require("vscode")` in each `extension.js`, list `alias.member`, and diff the two versions. For 2.1.330 → 2.1.331 that was 9 names, 2 of them needed at activation. Then check which ones are reached before implementing any.
- **CC 2.1.311 calls `vscode.env.onDidChangeTelemetryEnabled` during `activate`, and a falsy `isTelemetryEnabled` becomes `DISABLE_TELEMETRY=1` on the CLI** — that also stops feature-flag fetch. The shim follows VS Code: default level `all`, so the flag is true. See `isTelemetryEnabledFromConfiguration` in `env.js`.
- **Cheap A/B without building Canopy** — `HOME=$(mktemp -d) node <shim>/index.js --extension-path <ext> --cwd <dir> --settings-path <settings>` with stdin held open; failure exits 1, success prints `MCP Server running on port`. The scratch `HOME` is required (shared `storagePath`, real MCP port, `~/.claude/ide/<port>.lock`).
- **`canopyAssignedEnvKeys` is an explicit list, not a `CANOPY_*` prefix sweep** — a sweep would drop dev overrides like `CANOPY_CJK_DEBUG`. It is scrubbed in BOTH spawners (`ShimProcess`, `RemoteSessionsBridge`).
- **SSH patches in `index.js`**: `realpathSync` tolerates `ENOENT`; `spawn` rewrites a missing `cwd` to `$HOME` only for `CANOPY_SSH_WRAPPER_PATH` commands (others must fail cleanly). Per-session config goes through `envOverrides` in `workspace.js`, not the shared settings file.
- **`OutputChannel.show()` sends `show_document` from a per-channel ring** — see the comment above `OUTPUT_CHANNEL_MAX_LINES` in `window.js`.
- **`open_user_settings_file` is handled in `ShimProcess`** (`handleOpenUserSettingsFile`), and opens in the default editor. `showTextDocument` / `openTextDocument` now read `file:` Uris, which also changes the extension's other `openFile` and diff paths.
- **`createTerminal({shellPath})` writes a quoted `shellCommand`; Swift runs it in Terminal.app** (`window.js`, `ShimProcess.terminalShellLine`). Callers without `shellPath` must stay name-only (`sendText` is a stub); SSH refuses `shellPath`.
